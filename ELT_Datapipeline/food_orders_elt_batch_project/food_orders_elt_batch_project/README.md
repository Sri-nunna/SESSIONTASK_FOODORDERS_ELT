# Food Orders — Batch-Based ELT Pipeline

## 1. Project objective

This project implements the second part of the Food Orders assignment. It uses **Python, Pandas and MySQL** to extract the original CSV in batches of 100 rows, preserve it in a raw database, retrieve it in batches, transform and validate it, and load accepted records into a separate analytics database.

The source file is `data/food_orders.csv` (1,010 rows, 14 columns).

## 3. Pipeline architecture

1. **Extract:** `extract.py` reads the CSV using Pandas with `chunksize=100`. It only adds a source row number for traceability; it does not clean or transform source values.
2. **Load raw:** `load_raw.py` creates `food_orders_raw_db.raw_food_orders` and inserts each 100-row batch using `executemany()` and a database transaction. Raw source values are stored as text so the original CSV representation, blanks and duplicate rows are retained. A source row number is the primary key; it does not deduplicate business records.
3. **Retrieve raw:** `retrieve_raw.py` reads the raw table in deterministic source-row order, 100 rows at a time.
4. **Transform:** `transform.py` applies the documented rules to each retrieved batch. Duplicate fingerprints and seen Order IDs are maintained across batches, so duplicates split between batches are still detected.
5. **Validate:** `validate.py` checks schema, data types, duplicate status, delivery durations and revenue calculation rules. Rejected records and reasons are saved separately.
6. **Load analytics:** `load_transformed.py` creates `food_orders_analytics_db.cleaned_food_orders` and inserts accepted records in batches with transaction handling.
7. **Report:** `elt_batch_pipeline.py` prints and writes the final execution report to `reports/validation_report.json`.

## 4. Cleaning and transformation decisions

| Issue | Pipeline handling | Reason |
|---|---|---|
| Exact duplicate rows | Keep the first occurrence; reject later exact matches using a SHA-256 fingerprint of all source columns | Avoid double-counting while preserving the untouched raw table |
| Repeated Order ID | If a non-identical row reuses an already-seen Order ID, reject the later row for investigation | Order ID is treated as a transaction identifier |
| Missing Order Value | Retain as NULL | Do not invent a financial amount; exclude from SUM/AVG automatically |
| Missing financial components | Retain as NULL | Missing is not equivalent to zero |
| Missing Payment Method | Replace with `Unknown` in analytics data | Makes missing category explicit without guessing |
| Missing Discounts and Offers | Replace with `Not Specified` | Does not claim that no discount was applied |
| Invalid/missing timestamps | Reject record and record `invalid_or_missing_timestamp` | Delivery duration cannot be trusted |
| Negative delivery duration | Reject record and record `negative_delivery_duration` | Delivery cannot occur before the order |
| Revenue formula | Calculate only when all four components are present | Avoids understating/overstating revenue by treating unknowns as zero |

The simplified revenue formula is:

`Commission Fee + Delivery Fee - Payment Processing Fee - Refunds/Chargebacks`

`Platform_Net_Revenue` is an exercise metric, not a complete accounting definition.

## 5. Database setup

### Prerequisites

- Python 3.10 or later
- MySQL Server 8.x (or a compatible MySQL server)
- A MySQL account allowed to create databases and tables, insert, select and create indexes

Start the MySQL service and confirm that you can connect.

### Install Python dependencies

Open a terminal in the project folder:

```bash
python -m venv .venv
```

Windows:

```powershell
.venv\Scripts\activate
```

macOS/Linux:

```bash
source .venv/bin/activate
```

Install packages:

```bash
pip install -r requirements.txt
```

### Configure MySQL

Copy `.env.example` to `.env`, then enter your MySQL username and password. Do not commit `.env` to Git.

Example:

```env
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=your_actual_password
BATCH_SIZE=100
```

The pipeline automatically loads `.env` through `python-dotenv` and reads the settings as environment variables.

The pipeline creates the two databases and tables if they do not already exist:

- `food_orders_raw_db.raw_food_orders`
- `food_orders_analytics_db.cleaned_food_orders`

## 6. Run the pipeline

From the project directory:

```bash
python elt_batch_pipeline.py
```

The pipeline runs in this order:

`CSV → raw MySQL → retrieve raw batches → Pandas transform → validate → analytics MySQL → execution report`

The source CSV is loaded append-only using `source_row_number` as a primary key. **For a fresh repeatable run**, clear the two target tables before rerunning, or use fresh database names. This avoids primary-key conflicts and prevents accidental duplicate loads. Example SQL for a deliberate reset:

```sql
TRUNCATE TABLE food_orders_raw_db.raw_food_orders;
TRUNCATE TABLE food_orders_analytics_db.cleaned_food_orders;
```

Do not truncate the raw table if you need to retain previously ingested source batches.

## 7. Optional local preflight (no MySQL required)

Before connecting to MySQL, you can test the Pandas transformation and validation logic:

```bash
python preflight_transform.py
```

This writes `reports/source_preflight_report.json` and `reports/preflight_rejected_records.csv`. It does not create databases or claim that the MySQL load has run. The supplied project includes the preflight report generated from the attached CSV.

## 8. Review outputs

After a successful full run, inspect:

- `reports/validation_report.json` — currently a clearly labelled pre-execution report; the full MySQL run replaces it with counts, batch totals, validation checks and final status.
- `reports/rejected_records.csv` — generated by the full pipeline with rejected source rows and a `rejection_reason`.

A record with a missing Order Value can still be a valid order record. It remains in the analytics table with a NULL Order Value, but is excluded from order-value totals and averages. Revenue is NULL whenever one or more required formula components are missing.

## 9. Business analysis SQL

Open `sql/business_analysis.sql` in MySQL Workbench or another MySQL client. Select `food_orders_analytics_db` and run the queries for:

1. Total order value
2. Average order value
3. Payment method with the highest order count
4. Order channel with the highest order count
5. Average delivery time
6. Total platform net revenue and number of contributing records

## 10. Important operational notes

- Raw data is never updated by transformation code.
- All source rows, including duplicate records, are retained in the raw table.
- The raw table has a unique ingestion row number, not a unique Order ID constraint.
- Deduplication is global across the retrieved batches, not limited to one batch at a time.
- Every insert batch is committed as a transaction; a failed batch is rolled back and raises a clear error.
- The pipeline is designed for a clean first run. For reruns, follow the reset guidance above or implement a separate run/batch identifier for production-grade incremental ingestion.
- The actual MySQL execution report is generated only after the pipeline is run with a working MySQL connection.

## 11. Expected source-level batch count

For the supplied CSV (1,010 rows) and a batch size of 100, extraction is expected to produce 11 batches: ten batches of 100 rows and one batch of 10 rows. This is a source-file calculation, not a claim that the MySQL pipeline has already been executed.
